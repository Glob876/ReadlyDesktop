# Readly

Локальное приложение для заучивания стихов на **Rust + TypeScript + Electron**. Спокойный интерфейс с книжным шрифтом, светлой, тёмной и сепия-темой. Стиль ориентирован на локальный проект Typoha; код приложения написан отдельно.

![Главный экран Readly](screenshots/01-poem.png)

## Запуск

Нужны Node.js 22.12+ (или 24+), npm и стабильный Rust с Cargo. В Linux также нужны системные библиотеки Electron и работающая графическая сессия.

```sh
./run.sh
```

Скрипт установит npm-зависимости при первом запуске, соберёт приложение и откроет Readly. Его можно запускать из любого каталога.

Для разработки с автоматическим обновлением интерфейса: `npm ci`, затем `npm run dev`.

Собрать и запустить без сервера разработки:

```sh
npm run build
npm start
```

Переносимая папка для Linux текущей архитектуры:

```sh
npm run pack
./release/Readly-linux-x64/Readly
```

Папка содержит Electron, собранное Rust-ядро и интерфейс. Node.js и Rust на компьютере получателя не нужны. Сборку для другой ОС нужно выполнять на соответствующей системе; скрипт переносимой папки пока рассчитан на Linux. Электронный runtime сохраняет свои файлы лицензий в папке сборки.

## Занятие

В **Настройки → Стихотворение** вставьте текст. Строки разделяйте переносом, строфы — пустой строкой. На главной странице показан весь текст.

1. Каждая строка: переписать с образца, затем написать по памяти.
2. После строк: вся строфа с образца и по памяти.
3. После второй и каждой следующей строфы: предыдущая строфа с образца и по памяти, затем все выученные строфы вместе с образца и по памяти.
4. После последнего общего повторения занятие завершено.

Ошибочный ответ не продвигает занятие. Разбор показывает пропущенные, лишние и заменённые фрагменты с учётом правил проверки. Подсказки открываются ступенями: первое слово, первые буквы слов, первая строка, весь текст. После любой подсказки текущий шаг нужно повторить без неё. Enter переносит строку, **Ctrl + Enter** (или Cmd + Enter) проверяет ответ. Проверка происходит по нажатию кнопки, без таймера. Прогресс и статистика сохраняются после проверки. Незаконченный ввод сохраняется локально сразу и записывается в профиль с небольшой задержкой; он восстанавливается при возврате к занятию и перезапуске. Можно вернуться к тексту стихотворения и продолжить позже. Другой текст сохраняется отдельной записью: прогресс прежнего остаётся в личной библиотеке. Повтор с начала требует подтверждения.

В примере используется фрагмент «Зимнего утра» А. С. Пушкина, первые три строфы.

## Личная библиотека и режимы

Раздел **Мои стихотворения** хранит до 500 текстов с независимыми занятиями, черновиками и статистикой. Есть поиск, избранное и фильтры состояния. Изменённый текст сохраняется как отдельная запись; точное совпадение названия, автора и текста открывает существующую.

В **Параметрах занятия** на главной странице можно выбрать строфы и режим:

- **Учить с нуля** — обычная последовательность с образцом и по памяти.
- **Только по памяти** — без этапов переписывания.
- **Проверить целиком** — один ответ по выбранным строфам.
- **Трудные места** — повторение фрагментов с ошибками или подсказками.

Накопительное повторение можно ограничить блоками по 2, 3 или 4 строфы. Кнопка «Начать с этими параметрами» начинает новое занятие; обычное «Продолжить» сохраняет прежний план. История при перезапуске занятия остаётся.

**Статистика** показывает попытки, верные ответы, подсказки, завершённые занятия и трудные места текущего стихотворения. Хранятся последние 200 попыток, на экране отображаются последние 30. Завершение упражнения не называется доказательством долговременного запоминания.

После полного прохождения текста он попадает в **Повторение**. Чистые завершения последовательно назначают интервалы 1, 3, 7, 14, 30 и 60 дней. Ошибки или подсказки возвращают интервал к суткам. Частичное занятие и тренировка трудных мест не отмечают всё произведение пройденным. Системных уведомлений и фонового планировщика нет: очередь видна в приложении.

## Импорт, экспорт и восстановление

Кнопка **Импорт TXT** открывает локальный файл UTF-8 и показывает редактор для проверки названия, текста и строф перед сохранением. Название берётся из имени файла. Ограничения одного текста: 100 КБ, 100 строф, 2000 строк.

В **Настройки → Данные** можно экспортировать библиотеку в JSON вместе с прогрессом, статистикой и черновиками или импортировать её. Другие тексты сохраняются; для точных совпадений импорт заменяет сохранённый прогресс. Также поддерживается JSON-массив текстов с полями `title`, `author`, `text`. Некорректный импорт отклоняется целиком. Максимальный размер JSON-файла — 256 МиБ; экспорт проверяется на совместимость с импортом до записи. Экспортированный файл может содержать ваши личные тексты и ответы.

Здесь же выбирается резервная копия для восстановления всего профиля. Перед изменениями создаются копии предыдущего состояния; сохраняются последние пять. Оригинал повреждённого профиля сохраняется отдельно. Одновременно разрешён один экземпляр приложения на профиль; разные профили можно открыть независимо.

При потере связи с ядром кнопка **Восстановить связь** перезапускает его и перечитывает сохранение. Ответ не отправляется повторно автоматически. Размер и положение окна сохраняются между запусками.

## Библиотека классики

Раздел **Классика** содержит 422 стихотворения восьми авторов: Пушкина, Лермонтова, Тютчева, Фета, Некрасова, Жуковского, Баратынского и Кольцова. Поиск работает по автору, названию и словам текста; регистр и различие ё/е не учитываются. Можно выбрать автора, просмотреть полный текст и нажать **Выбрать для занятия**. Выбранный текст добавляется в личную библиотеку без сброса прогресса других произведений. Поиск дополнен фильтрами длины и статуса, а также сортировкой по названию, автору и длине. Выбранный текст сохраняется между запусками.

Каталог включён в сборку как JSON и не требует интернета, отдельного сервера или установки СУБД. Исходные строки и пустые строки между строфами сохранены. Использован раздел `klassika` из [PoetryCorpus Ильи Гусева](https://github.com/IlyaGusev/PoetryCorpus), снимок `7a5f70e6a46b4717f7c903671f9a6a917aee6162`. Оставлены только восемь перечисленных авторов, произведения от 4 до 120 непустых строк без явных цифровых сносок и примечаний со звёздочками; дубликаты исключены. Это автоматическая подборка, а не новая редакционная вычитка: варианты орфографии и пунктуации соответствуют исходному набору. Источник и исходное название доступны в просмотре каждого текста.

Лицензия репозитория источника — Apache License 2.0; её полный текст доступен в разделе «Об источнике библиотеки» и хранится в `src/data/PoetryCorpus-LICENSE.txt`. Каталог можно воспроизвести командой `python3 scripts/import-classics.py` (для повторного импорта нужен интернет; контрольная сумма источника проверяется). Для расширения достаточно обновить каталог, SQLite для такого объёма не требуется.

## Параметры

- Учёт регистра, пунктуации и различия ё/е включается независимо.
- По умолчанию сохраняется порядок строк; проверку переносов можно отключить.
- Точные пробелы: проверять отступы, повторные пробелы, пустые строки. Если отключено, лишние пробелы и пустые строки игнорируются.
- Светлая, тёмная, сепия или системная тема.
- Размер текста 18–34 px и непрозрачность фона 55–100%.
- Шрифт с засечками, без засечек или моноширинный; межстрочный интервал 1,2–2,4.
- Режим фокуса на экране занятия скрывает боковую панель.
- Вкладки настроек переключаются стрелками, Home и End; действия доступны с клавиатуры.

Прозрачным становится фон окна, текст сохраняет контрастность. Electron создаёт прозрачное окно; результат зависит от композитора и платформы. На некоторых Linux/Wayland-конфигурациях фон может оставаться непрозрачным. Изменения оформления показываются сразу; кнопка «Сохранить» записывает их, «Отменить» возвращает сохранённые параметры.

## Устройство

- `native/`: Rust-процесс, который разбирает строфы, строит последовательность заданий, нормализует ответы и записывает прогресс.
- `electron/`: изолированный preload и основной процесс Electron. Rust общается с Electron через JSON Lines в stdin/stdout; HTTP-сервера в готовом приложении нет.
- `src/`: интерфейс на TypeScript и CSS, без UI-фреймворка, внешних шрифтов и сетевых сервисов.
- `tests/`: интеграционные тесты ядра и сценарий настоящего приложения через Playwright Electron.

Данные лежат в `progress.json` в каталоге `app.getPath('userData')` (обычно `~/.config/readly-desktop/` в Linux). Запись через временный файл и атомарную замену. Если файл повреждён, приложение открывает экран восстановления и не перезаписывает его обычными действиями. Можно восстановить одну из пяти последних резервных копий, импортировать ранее экспортированную библиотеку или создать чистый профиль. Перед восстановлением повреждённый оригинал сохраняется отдельно как `progress.json.corrupt-<timestamp>` и не участвует в ротации копий. Старый формат одного стихотворения переносится автоматически; новые поля имеют значения по умолчанию. Для отдельного профиля можно задать переменную окружения `READLY_DATA_DIR`. Все данные локальны, телеметрии нет.

## Проверки

```sh
npm run build
npm test
cargo fmt --manifest-path native/Cargo.toml --check
cargo clippy --manifest-path native/Cargo.toml -- -D warnings
npm run test:ui
```

Для UI-тестов требуется графическая сессия (или `xvfb-run -a -s "-screen 0 1920x1080x24" npm run test:ui`). Тесты используют временные профили: проверяют занятия, подсказки и разбор, библиотеку, черновики после перезапуска, режимы, темы, повторения, импорт/экспорт и восстановление связи. `npm test` предварительно собирает release-ядро и Electron, чтобы не проверять устаревший бинарник. CI запускает сборку, проверки Rust/TypeScript и UI-тесты. Скриншоты сохраняются в `test-results/`.

## Логотип и иконки

Логотип «Раскрытая книга» из первого варианта Figma: цветной знак используется для окна и панели задач (`assets/icon.svg`, `assets/icon.png`), внутри приложения тот же SVG используется как монохромная маска и наследует цвет текста текущей темы. В переносимую сборку включены значок и ярлык `readly-desktop.desktop`. При запуске в Linux приложение регистрирует ярлык в пользовательском каталоге XDG, чтобы значок отображался и в Wayland.

Иконки интерфейса — [Lucide](https://lucide.dev/), SVG сохранены локально в `src/assets/icons/`; интернет и дополнительные runtime-зависимости не требуются. Источник, снимок и ISC-лицензия находятся рядом с файлами иконок; лицензия также включается в переносимую сборку.
